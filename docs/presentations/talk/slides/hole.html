The hole: the right package, under a name nobody searches

A pixi or conda environment is conda packages and PyPI packages, resolved together. NumPy comes from conda-forge, so a tool that does emit it names it the conda way.

What most tools write

pkg:conda/numpy@2.3.1

Correct, valid against the schema, and matched by almost no advisory database.

Where NumPy's advisories are filed

pkg:pypi/numpy@2.3.1

Same code, same version. The scanner only finds it under this name.

The document is present, well formed and hollow. Nobody chases an empty result that looks like a clean one.

[5-minute cut: yes. Full talk: 1:45–3:15. 5-minute: 0:20–1:35.] This is the whole problem in one slide. Nobody is lying here: the conda purl is correct. It is also the wrong key for the question we are asking, because Python advisories are filed against PyPI. A missing document gets noticed; a valid, hollow one gets filed and believed. If the room uses a Python-only scanner instead, the other half goes missing: it reads a requirements file and never sees what conda installed.
