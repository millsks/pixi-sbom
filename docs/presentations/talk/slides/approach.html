The fix: give every package both of its names

pixi-sbom reads the lockfile and writes CycloneDX or SPDX. A conda package that is a Python project keeps its conda identity and also gets its PyPI one.

numpy 2.3.4, from conda-forge

pkg:conda/numpy@2.3.4?build=py312h33ff503_0&channel=conda-forge

pkg:pypi/numpy@2.3.4

The PyPI name comes from the mapping conda-forge publishes, matched by the package's hash. A scanner can match either one.

[5-minute cut: skip. Full talk: 4:30–5:30.] This is the mechanism in one picture. Nothing is guessed from the package name: the conda-forge mapping identifies the PyPI project by the archive's hash, and the document records which source the identity came from. The conda purl stays, so anything that matched before still does. With --primary-purl pypi the PyPI one becomes the primary identity, for scanners that only read one.
