Why the tools already out there don't fit

Most SBOM tooling was built for pip, npm and Maven. A pixi environment is conda packages and PyPI wheels, resolved together into one lockfile.

What a generic tool sees

  • The wheels it recognizes
  • Conda packages as unknown, or missed entirely
  • No channel, build string or subdir
  • An inventory that looks complete and isn't

What pixi-sbom sees

  • Every locked package, both kinds
  • Channel, build, subdir and hashes
  • PyPI identity matched onto conda packages
  • The dependency graph the resolver picked
This is the answer to "why not just use what we already have". An incomplete SBOM is worse than no SBOM, because people trust it. If a scanner never sees the conda half of an environment, it comes back clean and the gap is invisible to everyone. Worth a sentence on the identity point: the conda build of numpy and the PyPI numpy are the same project, and matching them up is what lets a vulnerability database answer at all. Don't name competing products unless someone else does; this is about package ecosystems, not vendors.
