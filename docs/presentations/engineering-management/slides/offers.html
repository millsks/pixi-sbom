What it does

Both standards

CycloneDX 1.6 and 1.7, SPDX 2.3 and 3.0.1. Whoever asks gets the format they already use.

Known vulnerabilities

Looks them up in OSV, flags CISA's known-exploited list, and ranks the rest by how likely exploitation is (EPSS).

License rules

Allow and deny lists, with exemptions that have to carry a reason.

Provenance

Every fact records where it came from, including the sources that came back empty.

Supplier SBOMs

Grades a vendor's document before we trust it, applies their VEX, and merges it with ours into one.

Any Python project

pixi, uv, Poetry, PDM, conda-lock or pinned pip. From PyPI, a GitHub Action or a pre-commit hook.

Don't read the tiles out. Pick the two that matter to this room and let the rest sit there showing there's depth behind the pitch. For security and compliance, spend your time on provenance: the document records which sources were consulted and which returned nothing, so an auditor can tell "we checked and found nothing" from "we never checked". For engineering, "any Python project" is usually the one that gets a reaction: it does not care which tool locked the environment. If the room buys software from suppliers, supplier SBOMs is the tile for them: a vendor's document is graded and checked before anyone relies on it, instead of accepted on faith.
