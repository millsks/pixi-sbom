What it does

Both standards

CycloneDX 1.6 and 1.7, SPDX 2.3 and 3.0.1. Whoever asks gets the format they already use.

Known vulnerabilities

Looks them up in OSV and flags anything sitting in CISA's known-exploited list.

License rules

Allow and deny lists, with exemptions that have to carry a reason.

Provenance

Every fact records where it came from, including the sources that came back empty.

Release-to-release diff

What got added, dropped, upgraded or relicensed since last time.

A GitHub Action

Drop it in and the document comes out attached to the build.

Don't read the tiles out. Pick the two that matter to this room and let the rest sit there showing there's depth behind the pitch. For security and compliance, spend your time on provenance: the document records which sources were consulted and which returned nothing, so an auditor can tell "we checked and found nothing" from "we never checked". For engineering, the diff is usually the one that gets a reaction, because it turns "what changed in this release" from an afternoon of digging into a command.
